
# Attack Lab：理解缓冲区溢出漏洞

## 1 简介 (Introduction)

本实验包含针对两个具有不同安全漏洞的程序进行总共五次攻击。您将从本实验中获得的收获包括：

* 您将学习当程序没有充分防御缓冲区溢出时，攻击者利用安全漏洞的不同方式。
* 通过这些内容，您将更好地理解如何编写更安全的程序，以及编译器和操作系统为降低程序易受攻击性而提供的一些特性。
* 您将更深入地理解 x86-64 机器码的栈结构和参数传递机制。
* 您将更深入地理解 x86-64 指令是如何编码的。
* 您将获得更多使用 GDB 和 OBJDUMP 等调试工具的经验。

**注意**：在本实验中，您将亲身体验用于利用操作系统和网络服务器安全弱点的方法。我们的目的是帮助您了解程序的运行时操作，并理解这些安全弱点的本质，以便您在编写系统代码时能够规避它们。我们绝不赞同使用任何其他形式的攻击来未经授权地访问任何系统资源。

您可能需要研读 CS:APP3e 书籍的第 3.10.3 和 3.10.4 节，作为本实验的参考资料。

## 3 目标程序 (Target Programs)

`CTARGET` 和 `RTARGET` 都从标准输入读取字符串，它们使用的是如下定义的 `getbuf` 函数：

```c
unsigned getbuf() {
    char buf[BUFFER_SIZE];
    Gets(buf);
    return 1;
}

```

`Gets` 函数类似于标准库中的 `gets`，它从标准输入读取字符串并存储在 `buf` 缓冲区中。`Gets()` 和 `gets()` 无法确定目标缓冲区是否足够大，它们只是复制字节序列，这可能会越界覆盖分配的内存。

当您注入的字符串超过缓冲区时，通常会导致程序状态被损坏，触发内存访问错误（`segmentation fault`）。您的任务是构造特殊的**攻击字符串（Exploit Strings）**。

**重要提示**：

* 您的攻击字符串在任何中间位置都**不能包含字节值 `0x0a**`，因为这是换行符 `\n` 的 ASCII 码。当 `Gets` 遇到该字节时，会认为您终止了输入。
* `HEX2RAW` 接受以空格分隔的双位十六进制值。如果要生成十六进制 `0xdeadbeef`，需要传入 `"ef be ad de"`（注意**小端序**字节排列）。

## 4 第一部分：代码注入攻击 (Part I: Code Injection)

前三个阶段针对 `CTARGET`。该程序将栈位置设置为每次运行保持一致，且栈上的数据允许作为代码执行。

### 4.1 关卡 1 (Level 1)

* **目标**：不注入新代码，通过攻击字符串修改 `getbuf` 返回时的控制流，使其跳转去执行 `touch1` 函数，而不是返回到 `test`。
* **建议**：使用 `objdump -d` 查看反汇编代码，找到 `touch1` 的起始地址；注意小端序字节排列。

### 4.2 关卡 2 (Level 2)

* **目标**：将少量代码注入缓冲区。让 `CTARGET` 执行 `touch2` 的代码，同时必须将您的 `cookie` 作为参数传递给它。
* **建议**：
* 函数的第一个参数存放在 `%rdi` 寄存器中。
* 注入代码应将 `%rdi` 设置为您的 cookie，然后使用 `ret` 指令转移控制权给 `touch2`。
* 切勿在注入代码中使用 `jmp` 或 `call` 指令。

### 4.3 关卡 3 (Level 3)

* **目标**：同样是代码注入，但需要将 cookie 的**字符串表示**作为参数传递给 `touch3`。
* **建议**：
* 攻击串中需要包含 cookie 的 8 位十六进制字符串（如 `"59b997fa\0"`）。
* 注入代码将 `%rdi` 设置为该字符串的内存地址。
* **注意**：`hexmatch` 和 `strncmp` 函数被调用时会向栈中压入数据，**可能会覆写原本属于 `getbuf` 的缓冲区**。因此放置字符串时必须极其小心！

## 5 第二部分：面向返回编程 (Part II: Return-Oriented Programming)

程序 `RTARGET` 开启了两种防御机制，导致代码注入失效：

1. **栈随机化（ASLR）**：每次运行栈位置不同。
2. **栈不可执行（NX / DEP）**：栈内存被标记为不可执行，尝试跳转到栈上会导致段错误。

ROP 的策略是在现有代码段中寻找以 `ret`（字节码 `0xc3`）结尾的一串指令，称为 **Gadget**。通过在栈上串联各个 Gadget 的地址，利用 `ret` 指令实现链式跳转执行。

### 5.1 关卡 4 (Level 2 ROP)

* **目标**：在 `RTARGET` 上重复 Phase 2 的任务（调用 `touch2` 并传参 cookie），但只能使用 Gadget 农场中的指令。
* **可用指令类型**：
* `movq`（参见讲义图 3A）
* `popq`（参见讲义图 3B）
* `ret`（`0xc3`）
* `nop`（`0x90`，无操作）
* **建议**：所有需要的 Gadget 都可以位于 `start_farm` 和 `mid_farm` 之间，**只需两个 Gadget** 即可完成攻击。

### 5.2 关卡 5 (Level 3 ROP)

* **目标**：在 `RTARGET` 上通过 ROP 调用 `touch3` 并传递字符串指针。
* **说明**：可以使用 `start_farm` 到 `end_farm` 之间的扩展 Gadget，包含 `movl` 指令（图 3C）和 2 字节的功能性 `nop`（如 `andb %al, %al`，图 3D）。官方解法大约需要 **8 个 Gadget**。

## 附录 A 与 B：工具使用 (HEX2RAW & Byte Code)

### HEX2RAW 使用方法

`HEX2RAW` 接收十六进制文本作为输入，忽略以 `/* ... */` 包裹的 C 风格注释。常用调用命令：

```bash
unix> ./hex2raw < exploit.txt > exploit-raw.txt
unix> ./ctarget -i exploit-raw.txt

```

或直接使用管道：

```bash
unix> cat exploit.txt | ./hex2raw | ./ctarget

```

### 生成机器码

写好包含汇编的代码（如 `example.s`），利用 GCC 和 OBJDUMP 快速提取十六进制：

```bash
unix> gcc -c example.s
unix> objdump -d example.o > example.d

```

提取出的字节码直接填入攻击文本即可。
